# Publishing this repository safely

This repository is built to be publishable from the first commit rather than
sanitised before the first push. Nothing private is ever tracked, so there is no
history to rewrite and no cleanup step that can be forgotten.

Read this before you make it public anyway. Verification is cheap; a leaked key
in git history is not.

---

## Before you push

Run the audit:

```bash
uv run python scripts/pre_publish_audit.py
```

It inspects **tracked files** — what git would actually publish — not the working
tree, and it fails on any of:

| Check | What it catches |
|---|---|
| File extensions | A tracked `.key`, `.pem`, `.db`, `.log`, video, audio, or image file |
| Real config files | `.env` or `config/*.toml` tracked where only the `.example` belongs |
| Credential shapes | Anthropic, OpenAI, Google, GitHub, AWS, Slack keys, private-key blocks, credentials in URLs |
| Home paths | `/Users/…`, `/home/…`, `C:\Users\…` — your directory layout is nobody's business |
| Bind addresses | `0.0.0.0`, or an Ollama endpoint that is not loopback |
| Templates | Every required `.example` file still exists |
| `.gitignore` | Every category the specification requires is still covered |

The same audit runs as a pre-commit hook and as a CI job, so a regression fails
before it can be pushed rather than after.

Then run the secret scan across full history:

```bash
gitleaks detect --config .gitleaks.toml --source . --verbose
```

And the hygiene tests:

```bash
uv run pytest tests/unit/test_repository_hygiene.py -v
```

## What is deliberately not tracked

- `.env` and every real `config/*.toml` — only `.example` templates are committed
- The database, its WAL and SHM sidecars, and all runtime state
- Logs, lock files, PID files
- Model weights and caches
- **All source media** — every video, audio, and image extension
- All processed output: frames, transcripts, assembled documents, manifests,
  provenance, exports, collections, and analysis handoffs
- The design working reference in `design_reference/`
- OS and editor droppings

## What is in the templates

Structure and safe defaults. Nothing else.

No key, no token, no path from anyone's machine, no name, no email address, no
account identifier, no organisation ID, no private endpoint. The `base_url` for
the OpenAI-compatible provider is deliberately left empty in the template — a
real endpoint belongs in the git-ignored copy.

Model identifiers that do appear (`qwen2.5vl:7b`, `claude-sonnet-4-5`,
`gemini-2.5-flash`) are public product names offered as copyable suggestions, not
a catalogue and not anything private.

## Test fixtures are synthetic

No test uses personal media, a real API key, a paid call, a GPU, or a GUI
credential store. Video fixtures are generated by FFmpeg at test time from
colour patterns and tones. Transcripts and frames are synthesised. Every provider
is mocked. The credential-shaped strings in `tests/unit/test_redaction.py` are
runs of repeated characters with the right prefix — correct shape, no value, and
never valid anywhere.

## Continuous integration

The workflow declares `permissions: contents: read` and receives **no production
or release credentials**. It does not need any: the whole suite runs against
synthetic media and mocked providers, and the smoke test runs with networking
treated as unavailable.

If you later add a job that does need a secret, keep it off `pull_request`
triggers — a fork's pull request must never be able to read it.

## If something does leak

Rotate the credential first, at the provider. Do this before touching git: a key
that has been pushed to a public repository should be assumed compromised the
moment it lands, and history rewriting is slower than an automated scraper.

Then remove it from history with `git filter-repo` (or the BFG), force-push, and
ask GitHub Support to purge cached views of the affected commits. Forks and
existing clones keep the old objects regardless — which is why rotation, not
rewriting, is the actual fix.

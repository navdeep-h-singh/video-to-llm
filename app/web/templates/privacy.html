How it is enforced

Each of these is a property of the program, not a policy. Each has a test that fails if it stops being true.

  • The interface binds 127.0.0.1, and that is asserted when the application is constructed. It cannot be configured to listen anywhere else.
  • One check runs before every screen and every action: a request claiming a different host is refused, and so is any write or read arriving from another origin. Without it, a page you merely had open in another tab could delete a job or start one that spends money.
  • No page loads anything from anywhere else — no fonts, no scripts, no stylesheets, no images from a network. The badge in the header would be false the moment one did.
  • Your source videos are read where they are. Nothing is copied, moved, or altered.
  • Keys live in this computer's secure store — Keychain on a Mac, Credential Manager on Windows, the Secret Service keyring on Linux. Where there is no secure store, storing is refused rather than falling back to a file. No key is ever shown back to you, not even the first few characters, and none is written to the database, the logs, a manifest, an export, or a collection.
  • There are no accounts, no sign-in, and nothing is measured or reported about how you use this.
  • Describing on this computer never quietly becomes describing somewhere else. There is no automatic fall back to a paid service.
  • When a service is chosen, it receives the numbered still pictures and nothing else. Never the video file, never the audio, never the transcript. You are shown the count and the estimated cost first, and the run stops at a limit you set.

Checking for yourself

None of the above requires taking our word for it.

  • Disconnect from the network and process a video. Everything works.
  • Point a network monitor at this process. With descriptions off there is nothing to see.
  • Read docs/SECURITY.md in the repository, which lists what would count as a bug in any of this.
